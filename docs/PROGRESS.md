## M3 — Engine & analysis pipeline: done (host-verified; device checks pending)

Done:

- App: `MultistockfishDriver` (light flavor), `EngineService` (single owner, serial queue, lifecycle observer, hot-reload guard), `RepositoryAnalysisStore`, engine settings (Fast 12 / Normal 16 / Deep 20, threads `min(4, cores-2)`, Hash 64), board progress row (Starting / Queued + Cancel / Analysing k/N + Cancel / Cancelled, Paused, Unfinished + Resume / Failed + Retry / unreadable game), new games start analysing when their board opens.
- Review fixes (this pass): resume after pause never restarts (stored request has `restart=false`); pause / resume / cancel serialised (a resume during a still-stopping pause still resumes, never a second engine while the old one disposes, cancel always beats a racing pause); deleting a game cancels its job, and a game that vanishes mid-job ends `cancelled` instead of `engineCrashed`; startup reconciliation of `running` rows to `paused`; engine creation bounded by `PipelineTimeouts.engineStart` (30 s, interruptible by cancel / pause, a late engine is disposed); unreadable PGN -> `failed(invalidGame)` instead of an endless "Starting…"; re-enqueueing the running game with another depth/MultiPV or restart cancels and re-runs it; `begin` without clear keeps stored accuracies; library percentage counts positions and never shows 100% before `completed`; a cancel racing an idle timeout reports `cancelled`.
- Tests: core 131 (+3 skipped), app 99. Pipeline tests cover cancel mid-search, ignored `stop`, pause, resume, crash/retry, terminal positions, history on every `position`, P0 mirror, Chess960 start FEN (castling sent king-to-rook), en passant, underpromotion (`a7a8r`; `a7a8n` -> insufficient material, no engine call), and the race fixes above.

- Openings: the asset now also lists the **unnamed steps** of every named line (`epd\t\t` rows after the 3865 named ones; 7982 rows, new SHA-256), so the contiguous Book prefix follows theory through unnamed positions (Ruy Lopez 4.Ba4 Nf6 is Book now). Names still come from named rows only. `OpeningBook.contains`, `bookPositions`; builder test + `CHESS_OPENINGS_DIR` override for the reproducibility test.

Deviations / notes:
- **New transcripts were recorded with Stockfish 16** (Ubuntu package, `/usr/games/stockfish`, the only engine available in the cloud container), not 19; their headers say so. Expected labels were taken from these recordings; the M3 transcripts are still SF19. Re-recording with SF19 on the dev machine may move a few borderline cases (bands, line-2 gaps) and the vector JSON would then need updating; the classifier itself does not depend on the engine version.
- The recorded mirrored pairs do **not** give identical labels on every ply: Stockfish's fixed-depth search is not colour-symmetric (M3 pair: plies 6, 10, 15; SF16 pair: ply 5 lies at 0.052 vs 0.047 EP). The P0 test therefore checks exact equality on the mechanically mirrored transcripts and only the decisive moves + a 5 Win% tolerance on the recorded pairs (DECISIONS M4).
- Classification spec deviations (all in DECISIONS M4): Miss exception is `W_after <= 50` (SPEC `< 50`), a checkmating move is never Great, Best also for a line-2 move whose score ties line 1, captures' sacrifice test subtracts the captured material, final threefold / 50-move positions score 50, checkmate scores like a mate score (97.54) in classification and accuracy.
- `move_labels` rows are upserted per ply (no delete); a full re-classification always covers every ply of a completed analysis, so nothing stale remains in practice.
- A WIP snapshot commit (`a0c6092 WIP M4 ...`) appeared on the branch during this milestone; it was not made by the M4 worker, which left its later changes uncommitted as instructed.
